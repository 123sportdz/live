# التشغيل التلقائي الكامل

## ما الذي يعمل وحده؟

من لحظة نهاية البث إلى نسخة جاهزة للمراجعة:

1. **نهاية الجلسة** → تُضاف مهمة إلى الطابور (أو يلتقطها الماسح إن فاتت الإشارة).
2. **المقاطع** → CQT1 يحلّل التسجيل ويختار اللحظات ويرتّبها.
3. **الحلقة** → تُبنى حلقة 16:9 من المقاطع على التسجيل الأصلي: مقدمة، بطاقات، خاتمة، غلاف، فصول.
4. **الرفع** (اختياري) → الحلقة وأفضل المقاطع كنسخ **خاصة** في YouTube.
5. **إشعار** → Telegram/Webhook عند النجاح أو الفشل.

لا يُنشر شيء للجمهور تلقائياً إلا إذا اخترت «عامة» صراحة.

## قبل التفعيل

- [ ] `RECORD_ENABLED=true` — بدون تسجيل لا توجد مادة.
- [ ] CQT1 مثبّت ومجرّب: «فحص CQT1» يقول «جاهز».
- [ ] YouTube مربوط (إن أردت الرفع): زر «ربط YouTube» وصلاحية الرفع.
- [ ] مساحة حرة ≥ `PIPELINE_MIN_FREE_GB` (افتراضي 5GB).
- [ ] `SOURCE_RIGHTS` صحيح — التحذير يظهر إن كان `unknown`.
- [ ] المُرحّل متوقف أثناء التحليل (العامل ينتظر تلقائياً إن كان البث نشطاً).

## التفعيل

### من اللوحة

بطاقة **«التشغيل التلقائي»**:

- «تفعيل الأتمتة بعد كل جلسة».
- «تحليل المقاطع» و«بناء الحلقة» و«رفع نسخة خاصة».
- «حفظ الأتمتة».

### من `.env`

```env
AUTOPILOT_ENABLED=true
AUTO_CLIPS=true
AUTO_EPISODE=true
AUTO_UPLOAD=false
AUTO_UPLOAD_PRIVACY=private
AUTO_UPLOAD_MAX=3
AUTO_EPISODE_MAX_SEGMENTS=8
PIPELINE_MIN_FREE_GB=5
PIPELINE_POLL=60
PIPELINE_MAX_ATTEMPTS=3
```

## التشغيل مع الخدمة

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File packaging\install-windows-task.ps1
```

المهمة **Live Relay** تعمل عند تسجيل الدخول بالأمر:

```bat
.venv\Scripts\python.exe -m live_relay --service --dashboard-port 8765
```

تفتح اللوحة على `http://127.0.0.1:8765` بلا متصفح، ويبدأ المُرحّل والأتمتة. أوقفها من Task Scheduler.

### Linux (systemd)

```bash
cp packaging/live-relay.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now live-relay
journalctl --user -u live-relay -f
```

### يدوياً

```bat
.venv\Scripts\python.exe -m live_relay --service
```

أو اللوحة العادية `start_live_relay.bat` ثم «ابدأ».

> شغّل نسخة واحدة فقط. `--service` و`start_live_relay.bat` معاً = لوحتان ومُرحّلان محتملان. قفل عامل الأتمتة يمنع عاملين، لكنه لا يمنع مُرحّلين.

## الطابور والحالة

| المسار | المعنى |
|---|---|
| `state/pipeline/queue.json` | المهام وحالاتها (pending/running/done/failed) |
| `state/pipeline/scan.json` | آخر مسح للتسجيلات |
| `state/pipeline/worker.lock` | عامل واحد فقط |
| `state/pipeline/manifests/<id>.json` | ملف الحلقة المولّد |
| `state/episodes/auto-<date>-<id>/` | الحلقة الناتجة |
| `state/recordings/` | التسجيلات الأصلية |

- «شغّل على آخر تسجيل» يضيف مهمة يدوية تعمل حتى لو كانت الأتمتة متوقفة.
- «أعد المحاولة» يعيد المهمة الفاشلة ويبدأ من المرحلة الناقصة: المقاطع أو الحلقة المكتملة لا تُعاد.
- المهمة التي كانت تعمل عند إغلاق غير متوقع تعود `pending` عند تشغيل العامل.

## الرفع وحصة YouTube

- `videos.insert` يستهلك ≈1600 وحدة من أصل 10000 يومياً.
- `AUTO_UPLOAD_MAX=3` يعني 3 ملفات كحد أقصى لكل جلسة (الحلقة + أفضل مقطعين).
- عند `quotaExceeded` يتوقف الرفع وتُحفظ الملفات؛ أعد المحاولة في اليوم التالي.
- الخصوصية الافتراضية `private`. «عامة» تعني نشراً فورياً بلا مراجعة — لا تفعّلها إلا وأنت واثق.

## الأعطال الشائعة

| العرض | السبب | الحل |
|---|---|---|
| «التسجيل غير مفعّل» | `RECORD_ENABLED=false` | فعّله من الإعدادات |
| «عامل أتمتة آخر يعمل» | نسختان تعملان | أوقف الأخرى، أو احذف `worker.lock` بعد التأكد |
| «المقاطع: محوّل CQT1 غير مفعّل» | `CUTTER_ENABLED=false` أو المسار خطأ | «فحص CQT1» |
| «تخطي الحلقة: لا مقاطع» | CQT1 لم يعد بمقاطع | راجع التسجيل/المدة، أو استخدم القص فقط |
| «فشل الرفع: quota» | حصة YouTube | انتظر أو ارفع يدوياً |
| «المساحة أقل من الحد» | قرص ممتلئ | فرّغ مساحة أو خفّض الحد |
| المهمة عالقة `running` | العملية أُغلقت | أعد تشغيل الخدمة؛ ستُستأنف |

## الحدود

- التحليل يستخدم GPU/CPU؛ لا يبدأ أثناء بث نشط، لكنه قد يستمر إذا بدأ البث بعد انطلاقه. جدوله بعد الجلسة.
- جودة الاختيار تعتمد على CQT1 ونموذج Whisper؛ راجع المقاطع دائماً.
- لا يثبت حقوق المحتوى؛ `SOURCE_RIGHTS` إقرار منك.
- الأتمتة لا تتجاوز سياسة YouTube ولا ترفع محتوى ممنوعاً ببوابة CQT1.
